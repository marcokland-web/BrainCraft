## Technik (Stand 05.11.2026)

- Vite + React + TS als PWA, GitHub Pages unter `/BrainCraft/`; CSS aus Rechenstern übernommen (`src/styles/`), eigene Klassen mit `bc-` oder unter der Ansicht. Texte nur über `src/lib/i18n.ts`, Einstellungen in `src/lib/prefs.ts` (localStorage-Schlüssel mit `braincraft:`).
- Supabase-Projekt „Zähler“ `asfwbuptsfcrgmmgdgim`, geteilt mit Zähler, Gewohnheiten, Rechenstern. Alles in Schema `braincraft` (RLS an, keine Policies), Zugriff nur über `public.bc_*`. Nie Objekte anderer Apps anfassen.
- **Anmeldung (ab Migration 007, Stand 05.11.2026):** Eltern-Geräte (Handy, Mac) melden sich mit Google an (Supabase Auth, PKCE, `src/lib/auth.ts`, Sitzung in localStorage `braincraft-auth`); Familie über `auth.uid()` (`braincraft.family_parents`). **Kinder-Geräte haben nie eine Google-Sitzung:** Sie werden im Eltern-Cockpit gekoppelt („Gerät koppeln“: Einmal-Code XXXXX-XXXXX und QR-Link `#pair=…`, 10 Minuten, einmal, Fehlversuche gebremst) und bekommen ein Geräte-Token (`braincraft.devices`, nur als SHA-256), das jede Anfrage im Header `x-bc-device` mitschickt (`src/lib/api.ts`). Geräte-Liste und Entfernen nur auf dem Eltern-Gerät. Altgeräte tauschen ihren Familien-Code beim Start einmalig gegen ein Geräte-Token (`bc_device_from_code`, nur bis 008). Eltern-Cockpit überall nur mit der Eltern-PIN. Zugang verloren (Sitzung abgelaufen, Gerät entfernt, Familie weg): Runde/Boss laufen zu Ende, danach Kinderansicht „Gleich geht's weiter …“ (`src/views/Reconnect.tsx`), Stand und Warteschlange bleiben, Löschen nur nach roter Rückfrage. Fremde Familie (anderes Konto, Code einer anderen Familie): Rückfrage, nichts wird gesendet. Weitere Eltern per Gmail-Adresse einladen; Einladungen werden sichtbar angenommen oder abgelehnt (`bc_my_invites`, `bc_invite_accept`, `bc_invite_decline`), zählt nur die von Google bestätigte Adresse (`auth.identities`). Adressen in SQL (`braincraft.email_norm`) und JS (`src/lib/email.ts`) exakt gleich vereinheitlicht. Der live eingerichtete Before-User-Created-Hook liest `braincraft.parent_invites (email, expires_at)` und `braincraft.email_norm`: diese Namen nicht ändern. Im SQL keine Backslash-Escapes (MCP verfälscht sie), sondern `chr()`, `[[:space:]]`, `[.]`.
